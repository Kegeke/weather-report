# Implementation Plan: Telegram Bot Integration for Weather Report

## Summary
Add a Telegram bot (`WeatherBot`) to the existing weather-report project. The bot will reuse the existing HTTP client + Jackson JSON parsing from `WeatherApp.java` to fetch weather data from wttr.in and deliver formatted weather reports to Telegram users via Long Polling. The bot token will be read from an environment variable.

## Critical Context

| Item | Detail |
|---|---|
| **Project type** | Maven WAR, Java 26 |
| **Package** | `io.github.kegeke.weather` |
| **Key files to modify** | `pom.xml`, `WeatherBot.java` |
| **Key files to create** | `BotConfig.java`, `WeatherService.java` |
| **TelegramBots version** | `6.9.7.1` |
| **Existing JSON library** | `tools.jackson.core:jackson-databind:3.2.1` (NOT `com.fasterxml.jackson`) |

## Step-by-Step Implementation

### Step 1: Add TelegramBots dependency to pom.xml
**File**: `C:/Users/sidor/IdeaProjects/weather-report/pom.xml`

Add inside `<dependencies>`:
```xml
<dependency>
    <groupId>org.telegram</groupId>
    <artifactId>telegrambots</artifactId>
    <version>6.9.7.1</version>
</dependency>
```

### Step 2: Create BotConfig for bot token
**File (new)**: `src/main/java/io/github/kegeke/weather/bot/BotConfig.java`

- Static utility class with `getBotToken()` method
- Primary source: `TELEGRAM_BOT_TOKEN` environment variable
- Fallback: `src/main/resources/bot-token.txt`
- Throws `IllegalStateException` if neither is found

### Step 3: Extract WeatherService (reuse existing WeatherApp logic)
**File (new)**: `src/main/java/io/github/kegeke/weather/WeatherService.java`

- Encapsulates HTTP fetch + JSON parsing from `WeatherApp.main()`
- Uses `HttpClient.newHttpClient()` + `ObjectMapper`
- `fetchWeather(String city)` returns `WeatherResponse`
- Throws `IOException` on network/HTTP errors

### Step 4: Implement WeatherBot
**File (modify)**: `src/main/java/io/github/kegeke/weather/bot/WeatherBot.java`

- Extends `TelegramLongPollingBot`
- Commands:
  - `/start` — welcome message with usage instructions
  - `/weather [city]` — fetch and send weather report
- HTML-formatted responses with: location, temperature, humidity, wind, visibility, pressure, UV index
- Error handling: network errors, invalid cities, Telegram API errors
- `getBotToken()` delegates to `BotConfig.getBotToken()`
- `getBotUsername()` returns `"weather_report_bot"`

### Step 5: Update WeatherApp main() to launch the bot
**File (modify)**: `src/main/java/io/github/kegeke/weather/WeatherApp.java`

- Replace console output with bot initialization
- Register `WeatherBot` with `TelegramBotsApi(DefaultBotSession.class)`
- Print startup confirmation

### Step 6: Security — protect bot token
- Create `src/main/resources/bot-token.txt` for local dev (manually add token)
- Add `src/main/resources/bot-token.txt` to `.gitignore`

## Verification Steps

1. **Compile**: `mvn compile` — should succeed
2. **Set token**: `$env:TELEGRAM_BOT_TOKEN="YOUR_TOKEN"` or create `bot-token.txt`
3. **Run**: `mvn exec:java -Dexec.mainClass="io.github.kegeke.weather.WeatherApp"`
4. **Test in Telegram**:
   - `/start` → welcome message
   - `/weather London` → weather report
   - `/weather` (no city) → usage instructions
   - `/weather InvalidCityXYZ` → error message

## Open Risks

1. **Jackson conflict**: Project uses `tools.jackson` (Eclipse), telegrambots may pull `com.fasterxml.jackson`. May need `<exclusions>` if classpath conflicts arise.
2. **WAR packaging**: Project is WAR, but bot is standalone. Fine for `mvn exec:java` or IDE. For production, consider separate JAR or Docker.
3. **City encoding**: Cyrillic city names may need URL encoding for wttr.in API.
